## 恢复规则

| 情况 | 处理 |
|---|---|
| 暂时缺失/过期的独立状态、过期截图、观察期间移动 | 在观察次数和时间预算内重新获取 |
| 目标暂未出现、点击前图块/布局/状态变化 | 在定位预算内重新观察和定位 |
| 规划期间状态或布局改变，但窗口身份相同、全会话尚无可能输入 | 最多重新规划 1 次，新请求使用新截图和状态 |
| 重名且未指定 occurrence | 停止，不任意选择或靠重复请求消除歧义 |
| 已派发过输入，包括前序已验证步骤 | 后续失败时不自动重规划或重放动作 |
| 部分输入、提交后控制报错、验证不通过 | 条件允许时只读重新观察，保留失败与不确定状态 |
| 停止请求、焦点/HWND 改变、权限错误、预算耗尽 | 停止；不重新聚焦、不重试输入，不继续诊断读取 |
| HTTP 429、超时、鉴权、模型格式错误 | 不作为恢复触发条件，不自动重发请求 |

即使失败后观察到 OCR 和独立状态都满足最终目标，也不把“可能输入后报错”的会话改判成功。恢复仅在同一目标窗口内进行，不能跨窗口自动接管。

## 默认预算

配置见 [week3-thursday.json](../configs/week3-thursday.json)：每次观察最多 3 次尝试/5 秒；每步定位最多 3 次/8 秒；每步结果确认最多 10 秒且不超过原步骤 timeout；会话最多 60 秒、80 次观察尝试、12 次控制方法派发入口、1 次重规划；重试间隔 0.2 秒，截图最大年龄 2 秒。

时间使用单调时钟。预算是协作式限制：调用前后均检查，但不能硬中断正在阻塞的 OCR、HTTP 或系统输入调用；超时返回的结果不能继续触发输入。HTTP 的 socket timeout 会收紧到会话剩余时间。CLI 创建 OCR Reader 等初始化发生在恢复会话计时之前。

## 实现位置

| 文件 | 内容 |
|---|---|
| `gui_workflow/recovery.py` | 策略校验、共享预算、窗口约束、观察/定位恢复及逐步确认 |
| `gui_agent/recovery.py` | 多轮会话、零输入重规划、失败后只读观察、子任务依赖台账 |
| `gui_workflow/verification.py` | 独立状态错误可恢复性；错误 HWND、坏格式及权限原因不盲目重试 |
| `run_agent.py --recovery-policy ...` | 显式开启恢复；缺省沿用原单计划入口 |
| `run_recovery_demo.py` | 纯模拟恢复演示，不访问桌面或网络 |
| `gui_agent/recovery_http_fixture.py` | 本地 HTTP 固定响应，用于协议测试，不是真实模型 |
| `scripts/validate_week3_thursday.py` | 保存 30 组证据，或只读核对已保存记录 |

周三的模型动作质量仍未通过。本轮恢复策略与模型效果是独立结果；真实桌面恢复、NIM 和更广应用/缩放验证继续保留待测，周五可在专用窗口中补测鲁棒性。
